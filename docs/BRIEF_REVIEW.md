# SME LoanFlow｜Brief Review & MVP 砍 Scope

## 結論先講

MVP 應定位為「貸款申請準備 + 配對平台」，**不要**做成「AI 批貸款」。差異化在減補件、減人工初篩時間。

## 建議預設答案（待產品負責人蓋章）

| 盲點 | 建議 MVP 決定 | 設計影響 |
| --- | --- | --- |
| 平台法律身份 | 先寫「申請及配對平台，非最終批核」 | 結果頁、免責、品牌語氣 |
| 是否顯示產品／利率 | **不顯示**正式利率與產品比較 | 砍掉 Offer 比較頁 |
| KYC／公司查冊 | 身份證明 + BR 上載；查冊 API 預留 | 註冊不阻塞 |
| 董事／擔保人 | 第一階段只收申請人；擔保人後置 | 表單更短 |
| 電子簽署 | 不做 | 批核後流程簡化 |
| AI 初篩對客戶 | **不展示**紅黃綠燈 | 前端只顯示文件狀態／待確認 |
| 顧問即時聊天 | 先用通知 + 留言；非即時 chat | 訊息中心即可 |
| 文件保存期限 | UI 顯示「依政策／合作機構要求」 | 私隱設定可配置文案 |
| 接收機構 | 先「指定合作機構」抽象授權 | 不做銀行清單 |
| 初篩規則權限 | 僅 Administrator + Compliance 覆核 | Audit Log 必做 |
| 平台範圍 | Web mobile-first + Admin desktop；原生殼後置 | 本 repo 即此策略 |

## 文案地雷（必須擋）

禁止：保證批核、百分百成功、即時放款、零風險、AI 已批准、你不符合資格、一定可以借到。

改用：初步評估、申請方向、需要進一步覆核、可能需要補充資料、相關貸款機構最終評估。

## 技術／合規註記（非設計可獨斷）

- PDPO、AES-256、CDI、物業估價 API：介面預留，實作需法律／資安／後端確認
- OCR 修改必須保留：原始值、修改值、修改者、時間
- 三色燈：圖示 + 文字 + 觸發原因 + 建議下一步；禁止「建議拒絕」

## 建議第一版可點擊 Prototype（已實作）

1. 新用戶無抵押申請：`/onboarding` → `/apply`（選無抵押）→ 提交
2. 有抵押申請：`/apply` 選有抵押 → 物業淨值 → 文件
3. 顧問補件：`/admin` → 案件 → `/admin/supplements`

- 銀行登入連接（CDI）
- 原生 iOS／Android 專案
- 正式 RBAC 後端
- 電子簽署與放款後對帳
